# システム設計

`createMonitorSession()` が状態、タイマー、操作の適用を担当します。公開デモではブラウザで1つのセッションを生成し、同じタブの操作画面・モニターへ状態を渡します。ローカル演習ではNode.jsでルームごとにセッションを生成し、APIとSSEで同期します。

画面は、Next.jsが提供する接続UIと、既存の表示処理を維持したシミュレーター描画に分かれています。描画処理は状態スナップショットの受信と操作のコールバックを受け取り、通信方式に依存しません。シナリオの編集中は、充電進捗などの受信でタイムラインを作り直さず、操作履歴のみ更新します。

## 波形と音声

`ecg-canvas.js` が時刻、調律、模擬心拍数などから波形を合成します。端末のピクセル密度に合わせてCanvasを設定し、約6秒分が収まる速度で掃引します。掃引カーソルが進む帯だけを塗り直し、ショック時刻からの経過に応じて一過性の波形変化を重ねます。

音声はWeb Audioで扱います。ローカル演習のモニターが、利用者の操作で音声を有効にするとWAVを読み込みます。状態変化に応じて充電音、準備完了音、アラームを切り替えます。公開デモは無音です。

## 運用上の制約

- ローカル演習のルームは単一Node.jsプロセスに保持されます。プロセスを再起動すると演習状態が消え、異なるインスタンス間でも状態を共有しません。
- ルーム数は64、SSE接続数はルームごとに16です。SSE接続のないルームは、最後のアクセスから12時間経過後、新しいルーム参照の際に破棄されます。
- URLの接続IDはモニター閲覧と操作の両方に使えます。アカウント認証や役割別の権限を設けていないため、ローカル演習は信頼できるネットワークで運用します。

## 静的デモの公開

ローカルで `npm run build:demo` を実行すると、`out/` に静的サイトを生成します。公開先のルートに配信し、`/` または `/demo/` から開けます。ローカルで静的出力を試す場合は、`python3 -m http.server 8080 --bind 127.0.0.1 --directory out` を実行して `http://127.0.0.1:8080` を開きます。Vercel等に設定する場合は静的サイトとして、ビルドコマンドを `npm run build:demo`、公開ディレクトリを `out` に指定します。配備先での設定は未検証です。

生成対象はHTML、CSS、デモが使うブラウザ用JavaScriptに限定しています。LAN用API、Pico用コード、WAVは配信ディレクトリに含めていません。GitHub上のソース公開は別途、コピー元コード・WAV・参照意匠の公開範囲を確認してから行います。
